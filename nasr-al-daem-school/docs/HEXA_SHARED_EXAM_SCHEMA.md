# عقد مخطط الاختبارات المشترك

## الغرض والنطاق

توثّق هذه الصفحة عقد البيانات المشترك بين بوابة المعلم وبوابة الطالب للتكليفين `HEXA-AF-TEA-02` و`HEXA-AF-STU-02`. الهدف هو إبقاء الاختبار وأسئلته في بنية واحدة داخل مشروع Laravel الموحّد، ومنع إنشاء جداول أو Models بديلة عند دمج الفروع.

تعكس هذه الوثيقة بنية الشفرة الحالية. أي تغيير في الجداول أو العلاقات المشتركة المذكورة أدناه يحتاج مراجعة واعتماد إدارة الشركة قبل الدمج أو التطبيق في بيئة مشتركة.

الفحص الحالي للمستودع لم يجد جداول بديلة باسم `questions` أو `exam_question_options` أو `quiz_questions` أو `test_questions`. يجب الحفاظ على هذه النتيجة بعد دمج أي فرع.

## جدول `exams`

جدول `exams` هو رأس الاختبار المشترك، ويمثله `app/Models/Exam.php`. حقوله الحالية:

| الحقل | المعنى |
|---|---|
| `id` | المعرّف الرئيسي |
| `title` | عنوان الاختبار |
| `subject_id` | المادة المشتركة |
| `classroom_id` | الصف المخاطب بالاختبار |
| `teacher_id` | المعلم المسؤول |
| `starts_at` | وقت بدء الاختبار بحسب وقت الخادم |
| `duration_minutes` | مدة الاختبار بالدقائق |
| `total_score` | الدرجة الكلية المعلنة |
| `status` | حالة الاختبار؛ بوابة الطالب لا تعرض إلا `published` |
| `created_at`, `updated_at` | حقول التتبع |

العلاقات المعتمدة في Model هي `subject()` و`classroom()` و`teacher()` و`questions()` و`attempts()`.

يوجد في المستودع الحالي مسار إداري ينشئ رأس الاختبار داخل `exams`، لكن لا توجد في بوابة المعلم الحالية واجهة إنتاجية لإنشاء أسئلة الاختبار. بوابة المعلم الموجودة ضمن نطاق `HEXA-AF-STU-02` تعرض تسليمات الواجبات وتنزّلها فقط.

## جدول `exam_questions`

`exam_questions` هو جدول الأسئلة المشترك الوحيد، ويمثله `app/Models/ExamQuestion.php`. العقد الحالي لحقوله:

| الحقل | النوع المنطقي | العقد |
|---|---|---|
| `id` | مفتاح رئيسي | معرّف السؤال |
| `exam_id` | مفتاح أجنبي | يرتبط باختبار واحد، ويحذف مع الاختبار |
| `question_text` | نص | نص السؤال الأصلي الذي يكتبه المعلم |
| `type` | نص قصير | نوع السؤال؛ يدعم تنفيذ الطالب حاليًا `multiple_choice` و`true_false`، ويعامل الأنواع الأخرى كأسئلة تحتاج مراجعة يدوية |
| `options` | JSON nullable | الاختيارات المتاحة للسؤال الموضوعي |
| `correct_answer` | نص nullable | مفتاح الإجابة الصحيحة للأسئلة الموضوعية، وليس نصًا عامًا يعرض للطالب |
| `score` | decimal | الدرجة القصوى للسؤال |
| `position` | عدد صحيح | ترتيب السؤال داخل الاختبار |
| `created_at`, `updated_at` | تتبع | وقتا الإنشاء والتعديل |

يحوّل `ExamQuestion::answerOptions()` مصفوفة JSON ذات المفاتيح إلى خيارات كما هي، ويحوّل القائمة البسيطة إلى مفاتيح نصية. في السؤال الموضوعي يجب أن تطابق قيمة `correct_answer` أحد مفاتيح الخيارات الناتجة. وعند بدء الطالب للاختبار يتحقق التنفيذ أيضًا من أن مجموع `score` للأسئلة يساوي `exams.total_score`.

يخفي Model الحقل `correct_answer` عند التحويل إلى Array أو JSON، لكن هذه الحماية ليست بديلًا عن ضبط Controller وBlade؛ يمنع العقد تمرير السؤال الأصلي أو مفتاح الإجابة إلى HTML أو JavaScript قبل إنهاء المحاولة.

## توزيع المسؤوليات

### بوابة المعلم — `HEXA-AF-TEA-02`

المالك الوظيفي لإنشاء الاختبار وأسئلته هو بوابة المعلم بعد اعتماد نطاقها. عليها أن:

- تستخدم جدول `exams` نفسه وجدول `exam_questions` نفسه.
- تتحقق من أن المعلم مسند إلى الصف والمادة قبل إنشاء الاختبار أو تعديل أسئلته.
- تحفظ `question_text` و`type` و`options` و`correct_answer` و`score` و`position` وفق العقد أعلاه.
- تتحقق من صحة مفتاح الإجابة ومجموع الدرجات قبل نشر الاختبار.
- تمنع نشر اختبار بلا أسئلة أو بمجموع درجات لا يطابق `total_score`.
- تنسق تعديلات السؤال المنشور مع أثرها في المحاولات الجديدة؛ المحاولات التي بدأت بالفعل تبقى على Snapshot الخاص بها.

لا تضيف بوابة الطالب منشئ اختبارات أو منشئ أسئلة. كما أن وحدة المعلم الموجودة حاليًا في `app/Http/Controllers/TeacherPortal/AssignmentSubmissionController.php` ليست مالكًا لإنشاء الاختبارات؛ فهي وحدة قراءة وتنزيل لتسليمات الواجبات فقط.

### بوابة الطالب — `HEXA-AF-STU-02`

بوابة الطالب مستهلكة للمخطط المشترك، ومسؤولة عن:

- عرض اختبارات `published` الخاصة بصف الطالب فقط.
- التحقق من وقت البدء والمدة على الخادم.
- إنشاء محاولة مرتبطة بالطالب والاختبار وفق `app/Services/ExamAttemptPolicy.php` والقيمة المركزية في `config/student_academic.php`.
- إنشاء صفوف `exam_answers` من أسئلة الاختبار لحظة بدء المحاولة.
- عرض نص السؤال والاختيارات من Snapshot، وحفظ إجابة الطالب داخله.
- تصحيح الأسئلة الموضوعية من Snapshot، ووضع المحاولة التي تحتوي سؤالًا غير موضوعي في `pending_review`.
- تخزين النتيجة المرجعية في `exam_attempts` من دون الكتابة في `grades` إلى أن تعتمد آلية تتبع مصدر الدرجة.

لا يجوز لبوابة الطالب تعديل `exams` أو `exam_questions` أو كشف مفاتيح الإجابات.

## Snapshot المحاولة

ينشئ `app/Services/ExamAttemptService.php`، داخل Transaction، صفًا في `exam_attempts` وصفًا مقابل كل سؤال في `exam_answers`. الحقول التي تجمّد نسخة السؤال هي:

- `question_text_snapshot`
- `question_type_snapshot`
- `options_snapshot`
- `correct_answer_snapshot`
- `max_score`

أما `answer` و`answered_at` فهما إجابة الطالب ووقت حفظها، و`is_correct` و`awarded_score` ناتجا التصحيح.

يؤدي ذلك إلى بقاء المحاولة قابلة للتصحيح وفق المحتوى الذي بدأه الطالب، حتى إذا عدّل المعلم نص السؤال أو خياراته أو مفتاحه لاحقًا. يستخدم التصحيح `correct_answer_snapshot` و`max_score` ولا يعيد قراءة مفتاح السؤال الأصلي. كما أن المفتاح الأجنبي من `exam_answers.exam_question_id` يستخدم `restrictOnDelete()`، لذلك لا يجوز حذف سؤال مرتبط بمحاولة؛ التعديل أو الإيقاف أو الأرشفة يجب أن يراعي السجل التاريخي.

سياسة المحاولات الحالية مركزية وقيمتها الافتراضية `1`. يحمي `ExamAttemptService` الإنشاء المتزامن بقفل صف الطالب وTransaction مع إعادة فحص نافذة وقت الاختبار داخل المعاملة، وتفرض قاعدة البيانات uniqueness على `exam_id` و`student_id` و`attempt_number`. يسمح ذلك بتسلسل طلبات الطالب نفسه دون حجب بقية الطلاب الذين يبدأون الاختبار، وتسمح البنية بأرقام محاولات لاحقة إذا اعتُمد رفع الحد مستقبلًا، من دون توزيع قيمة سحرية في Controllers.

`correct_answer_snapshot` مخفي في `app/Models/ExamAnswer.php`. واجهة المحاولة في `resources/views/student/exams/attempt.blade.php` تعرض فقط نص السؤال والاختيارات المحفوظة وإجابة الطالب، ولا يجوز إضافة المفتاح الصحيح أو `is_correct` إلى الصفحة أو أي Payload قبل الإنهاء.

## قواعد الدمج ومنع الازدواج

- تبقى Migration واحدة فقط مسؤولة عن إنشاء `exam_questions` بعد دمج الفروع.
- يجب تنسيق ملكية `exam_questions` مع منفذ `HEXA-AF-TEA-02` قبل الدمج.
- يمنع إنشاء `questions` أو `exam_question_options` أو `quiz_questions` أو `test_questions` كبديل للعقد الحالي.
- يمنع إنشاء Model ثانٍ للسؤال؛ يستخدم الطرفان `app/Models/ExamQuestion.php`.
- إذا أضاف فرع المعلم حقولًا أو قيودًا، تدمج في Migration معتمدة واحدة أو في Migration إضافية متوافقة إذا كانت الأصلية قد استُخدمت في بيئة مشتركة.
- لا تعدّل Migration مطبقة أو مشتركة بين الفريق من دون قرار واضح؛ لا يحذف أي عمود أو بيانات قائمة أثناء تسوية الفروع.
- يجب تشغيل فحص كامل للمخطط والاختبارات على PostgreSQL Testing بعد تسوية الفروع وقبل الدمج.

## DATABASE APPROVAL REQUIRED

يلزم اعتماد الإدارة قبل الدمج في النقاط الآتية:

- تعيين مالك Migration `exam_questions` بين `HEXA-AF-STU-02` و`HEXA-AF-TEA-02`، مع بقاء منشئ واحد للجدول.
- اعتماد قائمة أنواع الأسئلة وقيمها الرسمية وصيغة JSON للاختيارات.
- اعتماد دورة نشر الاختبار وقواعد تعديل الأسئلة بعد النشر.
- اعتماد سياسة عدد المحاولات؛ التنفيذ الافتراضي الحالي محاولة واحدة وقابل للتوسعة، لكنه ليس قرارًا إداريًا نهائيًا.
- اعتماد أي حقول مشتركة جديدة، ومنها إعداد عدد المحاولات أو قيود `CHECK` على النوع والحالة والدرجات.
- اعتماد آلية تتبع مصدر الدرجة قبل أي مزامنة من `exam_attempts` إلى `grades`.

يجب تنسيق ملكية `exam_questions` مع منفذ `HEXA-AF-TEA-02`، وتبقى Migration واحدة فقط مسؤولة عن إنشاء الجدول بعد دمج الفروع.
