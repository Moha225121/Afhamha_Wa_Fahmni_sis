# تقرير تنفيذ مهمة أيوب محمد - HEXA-AF-PAR-02

## الهدف

تنفيذ المتابعة الأكاديمية والتواصل داخل بوابة ولي الأمر في مشروع Laravel الموحد، مع حماية ارتباط ولي الأمر بأبنائه، ودون منح ولي الأمر أي صلاحية لتعديل السجلات الأكاديمية أو أداء واجبات أو اختبارات.

## ما كان موجوداً قبل التنفيذ

- مصادقة موحدة وأدوار الإدارة والمعلم والطالب وولي الأمر.
- علاقة `guardians` إلى `students` عبر جدول `guardian_student`.
- بوابة ولي الأمر الأساسية: RTL، تصميم موجه للهاتف، PWA، لوحة، أبناء، ملف شخصي، ونتائج اختبارات منشورة.
- جداول الحضور والاختبارات والدرجات والإعلانات وإشعارات Laravel.
- لم تكن توجد جداول للواجبات أو المحادثات أو اشتراكات Push Notifications.

## ما تم تنفيذه

### 1. متابعة الابن المختار

- استُخدمت خدمة `ParentPortalContext` في جميع صفحات المتابعة لتجلب أبناء ولي الأمر فقط.
- أي قيمة `student` غير مرتبطة بحساب ولي الأمر ترجع 404، حتى إذا عُدّل الرابط يدوياً.
- أضيفت روابط سريعة للحضور والواجبات والاختبارات والإشعارات في لوحة ولي الأمر.

### 2. المتابعة الأكاديمية للقراءة فقط

- صفحة `parent/attendance`: النسبة والإجمالي والحالات وسجل الحضور، بلا مسار تعديل.
- صفحة `parent/assignments`: تعرض الواجبات المنشورة لصف الابن، موعدها، مرفقاتها وحالة التسليم فقط.
- صفحة `parent/exams`: تعرض الاختبارات المنشورة القادمة والسابقة، والنتيجة فقط بعد نشرها.
- صفحة النتائج صارت تسمّي البيانات بدقة: نتائج الاختبارات المنشورة.

### 3. المحادثات

- أنشئت محادثة مرتبطة بابن محدد.
- يستطيع ولي الأمر بدء المحادثة مع مستخدم إداري نشط، أو معلم نشط مسند إلى صف الابن فقط.
- لا يمكن فتح محادثة لا يشارك فيها الحساب الحالي.
- كل رسالة تحفظ المرسل والوقت، ويُحدّث وقت آخر رسالة ووقت قراءة كل مشارك.
- إرسال رسالة جديدة ينشئ إشعاراً للمستلم.

### 4. الإعلانات والإشعارات

- ظلت الإعلانات ملتزمة بجمهورها وصفوف الأبناء.
- عند نشر إعلان مناسب يتم إنشاء إشعار للوالدين المستهدفين.
- عند تسجيل غياب أو تأخر أو عذر للطالب يتم إشعار أولياء أمره.
- عند نشر درجة اختبار يتم إشعار أولياء أمر الطالب.
- أضيفت صفحة `parent/notifications` لعرض الإشعارات وتحديدها كمقروءة.

### 5. إشعارات الهاتف / PWA

- أضيف جدول `push_subscriptions` لحفظ اشتراك الجهاز بأمان للحساب نفسه فقط.
- أضيف زر تفعيل الإشعارات في صفحة الإشعارات بعد ضبط مفاتيح VAPID.
- جرى توسيع Service Worker الحالي لمعالجة أحداث `push` وفتح الرابط المرتبط عند النقر؛ لم يُغيّر التخزين المؤقت للصفحات الحساسة.
- أضيفت حزمة `minishlink/web-push` إلى `composer.json` و`composer.lock`.

## مخطط البيانات الجديد

| الجداول | الغرض |
|---|---|
| `assignments`, `assignment_attachments` | واجبات الصف ومرفقاتها المنشورة. |
| `assignment_submissions`, `assignment_submission_attachments` | حالة ووقت تسليم الطالب ومرفقاته. |
| `conversations`, `conversation_participants`, `messages` | محادثات ولي الأمر والمشاركين والرسائل ووقت القراءة. |
| `push_subscriptions` | أجهزة PWA المشتركِة في التنبيهات. |

هذه الجداول تضيف البيانات المشتركة اللازمة فقط؛ لم تُنشأ واجهات معلم أو طالب، ولم تُمنح بوابة ولي الأمر أي عملية كتابة على الواجبات أو الحضور أو الدرجات أو الاختبارات.

## المسارات الجديدة

| المسار | الوظيفة |
|---|---|
| `GET /parent/attendance` | متابعة الحضور. |
| `GET /parent/assignments` | متابعة الواجبات. |
| `GET /parent/exams` | متابعة الاختبارات والنتائج. |
| `GET, POST /parent/conversations` | قائمة المحادثات وإنشاؤها. |
| `GET /parent/conversations/{conversation}` | عرض محادثة مصرح بها وتحديدها كمقروءة. |
| `POST /parent/conversations/{conversation}/messages` | إرسال رد في محادثة مفتوحة. |
| `GET /parent/notifications` | مركز إشعارات ولي الأمر. |
| `POST /parent/push-subscriptions` | حفظ اشتراك هاتف الحساب. |
| `DELETE /parent/push-subscriptions/{subscription}` | حذف اشتراك يخص الحساب نفسه فقط. |

## إعداد الإشعارات الهاتفية قبل النشر

1. أنشئ مفاتيح VAPID في بيئة آمنة:

   ```powershell
   php artisan tinker --execute="print_r(\Minishlink\WebPush\VAPID::createVapidKeys());"
   ```

2. أضف القيم إلى ملف البيئة في الخادم، ولا تحفظ المفتاح الخاص في Git:

   ```text
   VAPID_SUBJECT="mailto:admin@your-school.example"
   VAPID_PUBLIC_KEY="..."
   VAPID_PRIVATE_KEY="..."
   ```

3. استخدم HTTPS في بيئة الإنتاج؛ المتصفحات لا تدعم Push على اتصال HTTP العادي، باستثناء `localhost` للتطوير.
4. بعد النشر يفتح ولي الأمر صفحة الإشعارات ويضغط **تفعيل إشعارات الهاتف** ثم يمنح الإذن للمتصفح أو تطبيق PWA.

## التحقق الذي تم قبل التسليم

- فحص صياغة PHP لملفات التطبيق والمخططات والمسارات والاختبارات: ناجح.
- تشغيل Laravel PHPUnit: **22 اختباراً ناجحاً، 89 تحققاً**.
- الاختبارات الجديدة تؤكد:
  - رفض الابن غير المرتبط في الحضور والواجبات.
  - عرض حالة تسليم الواجب للمتابعة فقط.
  - السماح بالمحادثة مع معلم صف الابن ورفض معلم غير مسند.
  - منع فتح محادثة أو حذف اشتراك جهاز يخص حساباً آخر.
  - حفظ اشتراك Push الخاص بالحساب.
- فحص المسارات الجديدة عبر `artisan route:list --path=parent`: ناجح.
- فحص بصري محلي عند عرض هاتف 390x844: صفحة اللوحة والصفحات الجديدة تظهر بتخطيط RTL متماسك، دون أخطاء متصفح مسجلة.

## ملاحظات التكامل

- يجب أن تستخدم بوابة المعلم/الطالب الجداول الجديدة للواجبات والتسليمات بدلاً من إنشاء جداول مكررة.
- صفحة ولي الأمر تعتمد على الواجبات المنشورة فقط، ولا تقدم أي زر تسليم أو تعديل.
- جميع البيانات الأكاديمية يجب أن تستمر في الإنشاء والنشر من البوابات المخولة لها، ثم تقرأ بوابة ولي الأمر النتائج المنشورة فقط.
