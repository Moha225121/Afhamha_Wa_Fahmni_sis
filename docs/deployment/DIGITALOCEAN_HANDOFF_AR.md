# تسليم المصدر الكامل — مدرسة النسبية — DigitalOcean

هذا هو المرجع التنفيذي للأوامر والإعدادات والترقية والخدمات والتراجع في حزمة المصدر الكاملة. نسخته داخل `source/docs/deployment/DIGITALOCEAN_HANDOFF_AR.md` ونسخته المسطحة في جذر الحزمة متطابقتان بايتًا. كل مسار كود أو وثيقة يبدأ بـ`app/` أو `docs/` أو ما شابه يُقرأ من **جذر source**؛ أسماء `RELEASE_MANIFEST.json` و`SHA256SUMS.txt` وملف ZIP تشير إلى غلاف الحزمة الخارجي. لهذا تُكتب المسارات نصيًا دون روابط نسبية تختلف عند قراءة النسخة المسطحة.

**قرار التسليم `HANDOFF_READY` منفصل عن قرار الإنتاج.** أثبتت دورة القبول مطابقة المصدر المفكوك وتثبيت اعتمادياته المقفلة وبناءه واختباره؛ بصمة المصدر والنتائج النهائية في `RELEASE_READINESS.md` و`TEST_EVIDENCE.md` المرفقين ونسختيهما المرجعيتين في `docs/qa/`. **قرار الإنتاج الحالي `PRODUCTION_NO_GO`** إلى أن يغلق مسؤول الاستضافة وفريق QA ومالك اعتماد المزود المتطلبات الخارجية أدناه. اكتمال التسليم لا يساوي تفويضًا بالنشر.

لم تُنفذ أوامر إنتاج أو اتصال بـDigitalOcean أو استعمال `.env` الحقيقية أو إرسال FCM/VAPID/Gemini حقيقي. لم يُنفذ commit أو push أو merge أو نشر. الأوامر التشغيلية أدناه إجراء مشروط للبيئة المعتمدة، وليست سجلًا لأوامر منفذة عليها. الأعداد النهائية وبصمة النسخة المقبولة تؤخذ من `docs/qa/TEST_EVIDENCE.md`، ولا تُكرر هنا أعداد دفعات جزئية قد تصبح قديمة.

## هوية النسخة ومحتوياتها

الهدف المؤكد من المستخدم هو **تطبيق مدرسة النسبية في جذر المستودع**. الفرع المحلي `codex/qa-release-readiness-20261108`، ومرجع البداية `1a5cfe27c72e38acd05c837682a3f29b0d7b3402`. الإصلاحات غير ملتزم بها؛ لذلك HEAD وحده ليس معرف الإصدار المسلم. المعرف العملي هو manifest الحزمة وبصمات ملفاتها وبصمة ZIP النهائية. النسخة الفرعية `nasr-al-daem-school` لم تُعدل أو تُضمّن بدل الجذر.

الحزمة الحالية **مصدر تطبيق كامل قابل لإعادة البناء**؛ لا تحتاج تطبيق فرق فوق نسخة أخرى أو وجود `.git`. يشمل `source/` التطبيق والمسارات والإعدادات والمخطط الأصلي والترحيلين الجديدين، والقوالب وJavaScript/CSS والأصول العامة الأصلية وPDF.js والأيقونات، وملفي القفل والاختبارات ومشغلات QA والوثائق. `scripts/qa/package-review.ps1` يولد فرق مراجعة تاريخيًا، ولا يُستخدم لبناء هذه الحزمة أو نشرها.

لا تُرفق `vendor` أو `node_modules` أو `public/build`؛ تثبت الاعتمادات من القفل وتُبنى الأصول في البيئة المستقبلة. لا تُرفق `.env` أو مفاتيح حسابات الخدمة أو `.git` أو بيانات المدرسة أو uploads الخاصة أو قاعدة/نسخة احتياطية أو جلسات أو سجلات أو cache مطور أو ثنائيات PostgreSQL. التقارير الأصلية ذات البيانات الشخصية خارج الحزمة. الأدلة وبيانات QA المرفقة اصطناعية ومنقحة. يحتفظ `storage` ببنية المجلدات الفارغة فقط؛ لا تستبدل به تخزين الموقع القائم.

يتحقق المستلم من بصمة ZIP الجانبية ثم `RELEASE_MANIFEST.json` و`SHA256SUMS.txt` **قبل تثبيت الاعتمادات أو توليد ملفات جديدة**. تستثني البصمات الداخلية ملفات البصمات نفسها والأرشيف لتجنب المرجع الذاتي؛ هي فحص سلامة وليست توقيعًا موثوقًا. فك الحزمة إلى مسار جديد، ولا تفكها فوق التطبيق النشط. احتفظ بالأرشيف الأصلي ونتيجة المطابقة.

## ما تحقق وحدود البيئة

نُفذت اختبارات SQLite المعزولة واختبارات **PostgreSQL 17.11 فعلي على Windows x86_64**، مع PHP 8.4.21 وامتدادي `pdo_pgsql` و`pgsql`. نجح بناء مخطط فارغ، ثم بناء المخطط السابق من 42 migration أصلية في HEAD المذكور، وزرع بيانات قديمة اصطناعية، وتطبيق الترحيلين الجديدين وفحص FK والملكية وعدم إعادة أحداث FCM القديمة. نجحت استعادة `pg_dump -Fc` فعلية إلى قاعدة جديدة عبر `pg_restore` مع مطابقة الصفوف وبصماتها وsequence المحادثات.

تكرر تحقق الترقية والاستعادة من `docs/deployment/BASELINE_MIGRATIONS.json` دون اعتماد على Git؛ يطابق المشغل بايتات ملفات المخطط السابق وملفي إعداد من HEAD قبل إنشاء نسخ مؤقتة تحت tmp. الملف قائمة بيانات غير تنفيذية؛ لا نسخة migration ثانية في docs أو deploy. نجح رفض manifest ذي بصمة متعمدة الخطأ قبل الترحيل. التفاصيل في `docs/qa/POSTGRES_VALIDATION_AR.md` و`docs/qa/evidence/postgres-validation.json`؛ نتائج المصدر المفكوك النهائية في `docs/qa/TEST_EVIDENCE.md`.

نُفذ تنافس بعمليتي PHP مستقلتين على PostgreSQL، وعامل ينتهي بعد قبول مزود مزيف ثم عامل يسترد المهمة. أثبت الفحص منع تكرار الإدخال والتعامل مع القفل، وأظهر احتمال قبول المزود مرتين عند ضياع الرد. تفاصيله في `docs/qa/CLOSEOUT_RELIABILITY_AR.md` و`docs/qa/evidence/fcm-postgres-concurrency.json`. نجحت فحوص متصفح محلية، ومنها مدخلات الصفوف على PostgreSQL وتثبيت/تحديث العامل المحلي وoffline والتخزين العام فقط. لا تحل هذه الأدلة محل اختبار الجهاز والمزود.

**بنية DigitalOcean الحالية وإصدار PostgreSQL فيها غير مؤكدين.** وصف `deploy/digitalocean/STATUS.md` تاريخيًا Droplet/Ubuntu 24.04 وNginx وPHP 8.3 وPostgreSQL محليًا. لا يثبت بقاء ذلك، ولا يحدد خدمة حالية أو مسارًا صالحًا للنشر. لم يُختبر Linux أو قاعدة الاستضافة أو حجم بياناتها أو زمن أقفالها أو استعادتها، ولم يُختبر Push على جهاز حقيقي أو Gemini فعلي.

## تأكيدات الاستضافة قبل التنفيذ

يثبت المسؤول في `docs/qa/DEVICE_STAGING_ACCEPTANCE_AR.md` نوع الخدمة: Droplet أو App Platform أو غيرهما، ومسار الإصدار وdocument root الذي يجب أن يكون `public/`، ومستخدم التشغيل، وطريقة تبديل الإصدار والتخزين الدائم وأسماء الخدمات الحقيقية. لا توجد هنا أوامر systemd/Supervisor أو مسارات تخمينية.

يؤكد إصدار PHP وامتداداته، وإصدار PostgreSQL وموقعه والاتصال الفعلي بعد أولوية `DB_URL`، وحقوق migration وحجم الجدولين المتأثرين، والنسخ الاحتياطي وخطوات الاستعادة، وحفظ `APP_KEY` وملفات المستخدمين، وتشغيل worker وscheduler ومخزن الأقفال المشترك. يحدد مشروع Firebase وإعداد Gemini وصلاحية تجربة المزود المحدودة. لا تُطبع كلمات المرور أو محتويات حساب الخدمة في الأدلة.

التطبيق Laravel/Blade موحد؛ بوابتا الطالب وولي الأمر تطبيقات ويب تدعم Service Workers وليستا تطبيقَي هاتف أصليين. يطلب `composer.json` PHP `^8.3`، ويتضمن القفل Laravel 13.30.0. القفل الأمامي يتضمن Vite 8.3.5 وFirebase 13.1.0؛ Vite يطلب Node `^20.19.0 || >=22.12.0`. فحص متطلبات القفل الفعلية هو الفيصل. لا تنسخ vendor أو وحدات Windows إلى Linux ولا تُحدّث القفل أثناء إعداد الإصدار.

التخزين الخاص `storage/app/private` والعام `storage/app/public` عبر `public/storage`. تبقى المكتبة والمرفقات الخاصة وراء مساراتها المصرح بها؛ لا تنقلها إلى public لتجاوز منع وصول. يثبت المسؤول الكتابة الضرورية على storage و`bootstrap/cache`، وHTTPS وMIME لملفات JavaScript وPDF.js من نوع `.mjs` و`.wasm`، وحماية جذر المصدر والأسرار من خادم الويب.

## البيئة: تغيير جديد واحد واعتمادات قائمة

التغيير الإنتاجي الجديد الوحيد هو `APP_DISPLAY_TIMEZONE`، اختياري وغير سري، افتراضيه `Africa/Tripoli`. الفراغ أو القيمة غير الصالحة يعودان إلى الافتراضي عبر `App\Support\DisplayTimezone`. الاستعمال الحالي: يوم/وقت chat وجهات الاتصال وقائمة محادثات مساعد المعلم. يبقى `app.timezone=UTC` للتخزين وISO وحدود الاختبار والجدولة؛ لا تحويل للسجلات القديمة ولا إضافة ساعتين يدويًا. تغيير القيمة يحتاج إعادة بناء config cache وتحديث العمليات طويلة العمر، ولا يحتاج Vite build بذاته. لم تتغير أسماء متغيرات إنتاجية أخرى ولم تُحذف. `ENV_CHANGES.example` نموذج لهذا التغيير فقط، ولا يُنسخ فوق `.env` القائمة.

| الإعداد القائم | الاستخدام والضبط المطلوب |
|---|---|
| `APP_URL` و`APP_KEY` و`APP_DEBUG` | عنوان HTTPS الصحيح، والمفتاح القائم محفوظ دون توليد بديل أثناء الترقية، وdebug معطل في الإنتاج. النطاق يؤثر في الروابط الموقعة وQR |
| `DB_CONNECTION` وحقول DB و`DB_URL` | اتصال البيئة المعتمدة بعد حل أولوية URL؛ لا قيم محلية من مشغلات QA |
| `DB_QUEUE_CONNECTION` و`DB_QUEUE_TABLE` و`DB_QUEUE` | اتصال database queue على اسم اتصال DB الافتراضي نفسه؛ يترك DB_QUEUE_CONNECTION غير مضبوط أو مساويًا له. الافتراضي jobs وصف default. يرفض outbox اتصالًا مختلفًا ويبقي الحدث معلقًا |
| `QUEUE_CONNECTION` | الطابور العام؛ حتى إن كان sync فإن FCM يستخدم database صراحة ويحتاج worker فعليًا |
| `DB_QUEUE_RETRY_AFTER` | الافتراضي 90 ثانية؛ يراجع مع مهلة worker ومدة القفل أدناه، ولا يغير منفردًا |
| `CACHE_STORE` واتصالات cache/lock | مخزن أقفال مشترك لكل العمال والمجدول؛ file مستقل لكل خادم أو array لا يحقق القفل بين خوادم متعددة |
| `FIREBASE_PROJECT_ID` و`GOOGLE_APPLICATION_CREDENTIALS` | runtime للويب والعامل؛ المشروع المعتمد ومسار حساب الخدمة خارج public وGit. محتوى الحساب سري ولا يوضع في VITE |
| `VITE_FIREBASE_API_KEY` و`VITE_FIREBASE_PROJECT_ID` و`VITE_FIREBASE_MESSAGING_SENDER_ID` و`VITE_FIREBASE_APP_ID` و`VITE_FIREBASE_VAPID_KEY` | إعداد Web App العام وقت البناء من المشروع نفسه؛ تغييرها يحتاج بناء public/build كاملًا. ليست بديلًا عن حساب الخدمة السري |
| `VAPID_SUBJECT` و`VAPID_PUBLIC_KEY` و`VAPID_PRIVATE_KEY` | قناة Web Push القائمة منفصلة عن FCM؛ الخاص سري وruntime. لا تخلط زوجها مع مفتاح Firebase VAPID العام |
| `GEMINI_API_KEY` و`GEMINI_MODEL` | تكامل المساعد القائم للطالب والمعلم؛ المفتاح سري على الخادم والنموذج وفق الإتاحة المعتمدة. لا متغير أو مزود جديد ولا إثبات لاتصال حي ضمن الحزمة |

متغيرات `QA_ALLOW_LOCAL_POSTGRES` و`QA_BROWSER_RUN` و`QA_NODE_MODULES` و`QA_BROWSER_EXE` وoverrides cache/storage في scripts/qa تخص الاختبارات فقط، ولا تُنقل للاستضافة. لا تستعمل fixtures أو demo seeders أو قواعد QA لإنشاء حسابات المدرسة.

## تثبيت المصدر من ملفات القفل

هذه أوامر إعداد **مجلد source المفكوك غير النشط**، من جذره. تُسمح تنزيلات الاعتمادات والبناء وفق سياسة بيئة البناء، ولا تعني اتصالًا بقاعدة الإنتاج. لا تشغّل `composer setup` أو `composer create-project` أو سكربتَي التثبيت التاريخيين `bootstrap.sh` و`install.sh` لترقية موقع قائم؛ قد تنشئ مفتاحًا أو قاعدة أو تطبق migrations تلقائيًا.

لنسخة قبول QA مع اعتماديات الاختبار:

```bash
composer install --prefer-dist --no-interaction --no-scripts --no-plugins
composer --no-plugins check-platform-reqs
npm ci --ignore-scripts
```

تمنع هذه الأوامر Composer hooks/plugins وnpm lifecycle hooks أثناء التثبيت؛ لا تشغّل migration أو key generation تلقائيًا. افحص checksum المصدر قبلها؛ الاعتمادات المولدة ليست ضمن manifest المصدر الأصلي. تستخدم إعادة الاختبار مشغلات العزل الموثقة في `docs/qa/TEST_EVIDENCE.md` و`docs/qa/POSTGRES_VALIDATION_AR.md`، ولا يُشغّل PHPUnit على `.env` أو قاعدة موقع قائم. يقبل مشغل الترقية manifest السابق من نسخة بلا `.git`.

لإصدار تشغيل منفصل بعد قبول المصدر، تثبت اعتماديات PHP دون dev:

```bash
composer install --no-dev --prefer-dist --no-interaction --no-scripts --no-plugins --optimize-autoloader
composer --no-plugins check-platform-reqs --no-dev
npm ci --ignore-scripts
```

بعد مراجعة البيئة الفعلية لذلك الإصدار ومطابقة قيم Firebase العامة وقت البناء، تنفذ تهيئة الحزم وبناء الأصول صراحة:

```bash
php artisan package:discover --ansi
npm run build
```

لا تفعّل الإصدار قبل نجاح البناء. انشر `public/build/manifest.json` وجميع chunks من البناء نفسه، مع `public/firebase-messaging-sw.js` الذي يستورد العامل المبني، وملفات `public/js/school-push-*` وأصول PWA. لا تستخدم build QA ذا إعدادات مزود معطلة بدل بناء المدرسة. لا يحتاج خادم الويب إلى node_modules وقت التشغيل؛ أبقِ ناتج البناء كاملًا.

## ترتيب النشر المشروط بعد إغلاق بوابة الإنتاج

1. يقبل المسؤول بصمة الحزمة ونتائج المصدر المفكوك، ويثبت البنية والإعدادات. يُختبر الإصدار على staging مماثل، وتُسجل نتائج القبول الخارجية ويصدر قرار إنتاج منفصل. حتى ذلك الوقت يبقى `PRODUCTION_NO_GO`.
2. تحفظ نسخة DB متسقة وuploads والمفتاح والإعدادات بأمان، وتنجح استعادة منفصلة. تُنسق نافذة الكتابة وإيقاف worker/scheduler، ويُحتفظ بالكود والأصول السابقين. snapshot غير مجربة ليست إثبات استعادة.
3. يُجهز الإصدار غير النشط واعتمادياته وأصوله كما سبق، مع ربط التخزين القائم والإعدادات المعتمدة. لا تنسخ storage الفارغ أو `.env.example` فوق بيانات الموقع، ولا تولد APP_KEY جديدًا.
4. من مجلد الإصدار المعتمد، يراجع المسؤول سجل المخطط:

```bash
php artisan migrate:status
```

يجب أن يكون فرق الترقية لهذا التسليم هو الترحيلين المذكورين فقط. ظهور migrations أقدم غير مطبقة أو مخطط مختلف يحتاج مراجعة فرق الأساس. بعد الموافقة على القائمة والنسخة الاحتياطية، تطبق الملفات الأصلية المحددة بترتيبها:

```bash
php artisan migrate --path=database/migrations/2026_11_08_000001_add_fcm_outbox_payload.php --force --no-interaction
php artisan migrate --path=database/migrations/2026_11_08_000002_add_teacher_owner_to_tutor_conversations.php --force --no-interaction
```

لا `migrate:fresh` أو seed أو `key:generate` على الموقع القائم. لا تفعّل الكود أو العامل الجديد قبل نجاح المخطط. إذا فشل الثاني بعد نجاح الأول، تحتفظ بالحالة والنسخة الاحتياطية وتوقف التبديل للتحقيق؛ لا rollback عام تلقائيًا.

5. بعد نجاح المخطط وضبط الإعدادات، يبني المسؤول cache الإصدار:

```bash
php artisan config:cache
php artisan route:cache
php artisan view:cache
```

يبدل الإصدار بآلية الاستضافة المثبتة ويعيد تحميل PHP/OPcache والعمليات طويلة العمر بأسمائها الحقيقية، ثم يعيد worker/scheduler. `php artisan queue:restart` إشارة خروج لطيف فقط، وليست إنشاء خدمة أو إثبات عودة عامل؛ تستعمل بعد تأكيد المشرف ومخزن cache المشترك.

6. يتحقق من public/storage والتخزين الخاص وبقاء الملفات. للتشخيص بعد ضبط البيئة:

```bash
php artisan library:verify-files --fail-on-error
```

الفشل لا يأذن بحذف ملف أو سجل. تُستكمل فحوص القبول والمراقبة قبل إغلاق النافذة.

## تشغيل FCM والطابور والجدولة

عند وجود جهاز FCM، يحفظ `record` الإشعار الداخلي وحدث outbox في المعاملة نفسها؛ يشارك معاملة المصدر إذا كانت قائمة. الاستدعاء بعد التزام المصدر لا يجعل المصدر ذريًا بأثر رجعي. `dispatch` المباشر ينشئ الحدث دون إشعار داخلي. يحتوي الحدث payload قبل commit، ويؤجل إدراج job فقط إلى ما بعد commit. يقفل enqueue صف الحدث ويُدخل job وqueued_at معًا على قاعدة الاتصال نفسها. فشل الإدراج يحتفظ بالحدث معلقًا، ويظهر تحذير تسليم معلق في المسار المعني دون إنكار حفظ العمل.

يفحص `fcm:retry-pending` حتى 100 حدث في كل مرة، لها payload وqueued_at/sent_at فارغان، كل دقيقة مع withoutOverlapping. لا يعيد الأحداث القديمة بلا payload، ولا يعيد job دخل الطابور ثم فشل نهائيًا. قفل الصف والمعاملة يمنعان إدخال job مكرر؛ لا ضمان مرة واحدة لدى المزود إن قبل الرسالة ثم فُقد الرد أو توقفت العملية قبل حفظ الإيصال.

job يستخدم database، وأربع محاولات، وbackoff `[10,60,180]` ثانية. قفل الحدث المشترك `WithoutOverlapping` له **releaseAfter(60)** و**expireAfter(120)**؛ تصادم القفل يستهلك محاولة، فلا يُخفض التأجيل إلى القيمة القديمة 10. ضمان الإدخال يعتمد على صف outbox والمعاملة؛ Queue::push لا يفعّل افتراضًا قفل PendingDispatch الخاص بـShouldBeUnique.

بعد تأكيد البنية، أمر عملية worker من مجلد الإصدار وبهوية التشغيل المعتمدة هو:

```bash
php artisan queue:work database --queue=default --sleep=3 --tries=4 --timeout=60
```

يفترض الأمر `DB_QUEUE=default`؛ إن اختلفت يجب مطابقة اسم الصف. يشرف عليه النظام الفعلي ويعيده بعد الفشل/إعادة التشغيل. مهلة 60 أقل من retry_after الافتراضي 90 ومن مدة القفل 120؛ يؤكد المسؤول دعم timeout في PHP/PCNTL وضبط القيم معًا. مهلة طلب المزود 15 ثانية لكل جهاز، وقد تتعدد الأجهزة؛ لا تُرفع مهلة العامل فوق مدة القفل دون مراجعة التصميم واختباره. يلزم cache lock مشترك لكل العمال، لا file مستقل على عدة خوادم.

يستدعي المجدول أمره مرة كل دقيقة من مسار الإصدار المعتمد، ولا يضاف cron ثانٍ فوق مجدول قائم:

```bash
php artisan schedule:run
```

ويتحقق المسؤول من الجدول الفعلي:

```bash
php artisan schedule:list
```

تعمل `student-exams:finalize-expired` و`results:publish-due` و`announcements:notify-due` و`fcm:retry-pending` كل دقيقة، و`library:prune-uploads` يوميًا، و`finance:send-reminders` الساعة 08:00 UTC. متغير العرض لا يحول هذه المواعيد. يحتاج فحص الاستضافة إثبات عمل المجدول والعامل بعد إعادة التشغيل، لا مجرد ظهور اسميهما.

للتشخيص المصرح يراجع المسؤول jobs وfailed_jobs وعمر outbox المعلق، وسجل `FCM event is stored and awaiting queue retry.` دون مشاركة payload أو tokens. يمكن استدعاء الاسترداد بعد معالجة سبب الاتصال:

```bash
php artisan fcm:retry-pending
php artisan queue:failed
```

تُراجع المهمة الفاشلة نهائيًا مع UUID والسبب وعلاقة الحدث، ثم يعاد UUID المحدد فقط باستخدام `php artisan queue:retry` مع ذلك المعرف. لا `retry all` ولا مسح جماعي لـqueued_at أو إيصالات الأجهزة. `queued_at` يثبت دخول الطابور، و`sent_at` اكتمال معالجة job وفق السياسة وقد يكتب عند غياب الأجهزة أو تعطيل الحساب؛ كلاهما لا يثبت ظهور التنبيه أو قراءته. قناة VAPID الحالية متزامنة ومنفصلة ولا ترث outbox وضماناته تلقائيًا.

## خصوصية Push وPWA والتوقيت والمساعد

يحمل FCM بيانات فقط مع `recipient_user_id` من حساب الخادم، ويعيد فحص ملكية الجهاز قبل الإرسال. تستخدم مقدمة Firebase وعامله وعامل ولي الأمر بوابة عرض واحدة تستعلم عن الجلسة الحالية من `/fcm-devices/status` عبر same-origin وno-store. لا تعرض رسالة بلا مستلم أو لحساب سابق، وتغلق الإشعارات القديمة المخالفة. عند انتهاء الجلسة أو تعذر فحصها أو غياب الاتصال **يُمنع العرض**؛ لا وعد بوصول التنبيه الخاص في وضع offline. يبقى إشعار المنصة الداخلي مستقلًا.

يعيد النقر فحص الجلسة ويحصر الوجهة في نفس الأصل وبوابة الدور الحالي، وإلا يعود إلى login. ينظف الخروج وتبديل الصفحة إشعارات تسجيلات المدرسة فقط دون إلغاء عمال أخرى. لا يثبت ذلك قفلًا ذريًا بين تغير cookie ولحظة عرض نظام التشغيل، ولا يسحب بطاقة عرضتها نسخة عامل قديمة على جهاز لم يحدث. tag ثابت للحدث يقلل ازدواج البطاقة لدى المتصفح الداعم، ولا يضمن exactly-once أو عدم تكرار التنبيه. يسجل فحص الجهاز تبديل الحساب والخروج والرسالة المتأخرة والإذن والشاشة المغلقة صراحة.

يحفظ cache الخاص بـPWA أصولًا عامة وصفحات offline فقط؛ dashboard والدرجات والرسائل لا تُخزن فيه. نجح تثبيت/تفعيل العامل وتحديثه محليًا وفحص offline، لكن تحديث تطبيق مثبت وتبديل الحساب على هاتف فعلي يحتاج مصفوفة الجهاز. لا تستخدم cache قديمًا أو أصول إصدار مختلف مع العامل الجديد.

مسار `/teacher/tutor` يخص المعلم النشط وملكه فقط، وسياقه خالٍ من درجات وقوائم الطلبة؛ محادثة الطالب مستقلة. معرف الإنشاء يمنع تكرار المحادثة للمعلم نفسه، ومعرف الرسالة يمنع تكرار إرسالها. يُحفظ السؤال وحالة الفشل عند تعذر المزود دون إجابة فارغة مصطنعة. لا يثبت الاختبار المحاكي سبب خطأ تاريخي بلا مسار أو إتاحة نموذج Gemini. تجربة مزود حية محدودة بحساب اصطناعي ونص عام تحتاج التفويض المعتمد وتسجل منفصلة.

## القبول والمراقبة والتراجع

يستخدم فريق QA `docs/qa/RETEST_CHECKLIST_AR.md` و`docs/qa/DEVICE_STAGING_ACCEPTANCE_AR.md` بحسابات وبيانات اصطناعية. يتأكد من `/up` وlogin والأصول وغياب 500، والصلاحيات من الخادم، والصفوف والعلاقات ورفض IDs غير الرقمية، والبطاقة وQR الموقّع، والمرفقات المصرح بها ومنع الغريب، والواجب وتصحيحه ونشره، والاختبار قبل الموعد ونتيجته، وعزل ملكية مساعد المعلم، وتوقيت Tripoli عبر منتصف الليل، والقائمة والجداول على الهاتف. يختبر العامل والمجدول والملفات وPWA/Push/Gemini بالأدلة المناسبة لكل مستوى.

تُراقب أخطاء التطبيق وfailed_jobs وعدد/عمر outbox المعلق، وتطابق الإشعار الداخلي والحدث وإيصالات الأجهزة دون كشف محتواها. نجاح HTTP لا يغني عن متصفح، ونجاح متصفح محلي لا يغني عن جهاز أو مزود. قرار كل بند في `docs/qa/QA_EXECUTION_STATUS.md` و`docs/qa/RELEASE_READINESS.md`، وآخر الأعداد في `docs/qa/TEST_EVIDENCE.md`.

**رجوع التطبيق:** يحتفظ المسؤول بالإصدار السابق وأصوله، وينسق العمال والجدولة والكتابة ثم يعيد الشيفرة والأصول والكاش والخدمات المتطابقة. تبقى أعمدة outbox وpayload وqueued_at وأعمدة ملكية المعلم وقابلية student_id للفراغ؛ لا تُسقط لاستعادة التطبيق. تراجع قابلية معالجة jobs والسجلات الجديدة بالشيفرة السابقة؛ لم يُثبت hot rollback بين إصدارين على الاستضافة.

**استعادة البيانات:** إجراء منفصل يعتمد على نسخة متسقة وخطة لتسوية ما كتب بعدها من مدفوعات ورسائل وإيصالات. نجحت الاستعادة الاصطناعية على PostgreSQL المحلي؛ لا تثبت قدرتها أو زمنها على بيانات الاستضافة. down الأول يفقد بيانات الاسترداد الجديدة، والثاني يرفض وجود سجل معلم أو محادثة بلا طالب. لا rollback عام معتمد هنا، ولا تجاوز للحارس بحذف محادثات أو اصطناع ملكية طالب.

يغلق مسؤول الاستضافة فجوة البنية والإصدار والتخزين وقياس الترحيل والنسخ والاستعادة والخدمات؛ ويغلق فريق QA فجوة staging والجهاز؛ ويغلق مالك اعتماد المزود تجربة FCM/VAPID/Gemini المحددة. عند اكتمال المصدر والقبول النظيف يستطيع المنسق تسجيل `HANDOFF_READY` مع بصمته. يظل `PRODUCTION_NO_GO` حتى توثيق المتطلبات وصدور قرار إطلاق منفصل؛ لا يتحول نجاح التسليم إلى نشر تلقائي.
