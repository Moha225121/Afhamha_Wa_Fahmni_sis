الهوية والاستثناءات والنظافة

بقيت النسبية إعداديًا وثانويًا بشعبيها العلمية والأدبية، والشعار والألوان والصور وCairo والبطاقة والجدول وإعداداتها. لم يُعتمد ترحيل الابتدائي أو بيانات مدرسة المصدر. يوجد أصلًا في main مجلد nasr-al-daem-school يحوي653 ملفًا tracked؛ لم يُضف أو يُعدّل بهذه الترقية ولم يُحذف عمل الفريق. ليس هدف نشر، ويجب أن يبقى document root هو public فقط.

اختبارات نشر المصدر14 لم تُعتمد ولم تُحسب ناجحة. أُزيل ملفها المنسوخ غير المتعقب لأنه يعتمد سكربتات وخدمات مصدر غير معتمدة؛ مشغّل JavaScript لا يخفيه باستثناء خاص بعد الآن. بيانات قواعد QA وحساباتها وملفاتها ومفاتيح البيئة والسجلات والبناء وvendor/node_modules لا تدخل Commit. تبقى fixtures المصطنعة اللازمة لاختبارات المصدر ومقطع runtime-check المصطنع موارد اختبار/تشخيص مقصودة، ولا تتضمن بيانات مدرسة حقيقية.

جاهزية المراجعة والنشر

جاهز لمراجعة Pull Request مع الإفصاح عن الحدود. جاهزية staging مشروطة بإذن مستقل وتجهيز خادم وقاعدة وتخزين معزولين والتحقق من runtime والعمال والجدولة وpreflight. الإنتاج غير معتمد.

  • Preserve existing APP_KEY and secrets; do not run baseline composer setup/key:generate against an existing school deployment.
  • Private persistent storage, ownership under actual PHP-FPM user, backups/restoration and disk/resource limits. Attached lesson-uploads/.../body.part files are referenced content, not disposable staging.
  • FFmpeg and proc_open under PHP-FPM; run full decode/storage receipt check in authorized staging. CLI success alone does not establish FPM/nginx/proxy upload readiness.
  • Persistent database notifications worker; application/jobs/batching databases aligned, retry_after greater than 60-second job timeout, Linux pcntl signals/timeouts, failure monitoring and worker restart procedure.
  • Scheduler for existing approved result releases and exam expiry plus scoped temporary-upload cleanup; no production scheduler or cleanup was executed during audit.
  • Firebase/legacy VAPID configuration, external credentials kept outside checkout, HTTPS, matching worker scope/build and a real authorized device before asserting phone delivery.
  • Review migrations and data anomalies/locking/disk/maintenance plan against a protected staging copy of the school database. Do not execute destructive rollback; up safety does not make down safe.
  • Deploy only the Laravel public document root. Existing nested source copy is unchanged history, not an additional running application or newly adopted deployment.
