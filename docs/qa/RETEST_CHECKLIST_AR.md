# قائمة إعادة اختبار الإصدار

هذه خطوات تنفيذ لفريق QA على النسخة المحددة ببصمة التسليم، وليست ادعاءً بأنها نفذت جميعًا. النتائج الفعلية والأعداد النهائية الحالية واختبار المصدر المفكوك في [TEST_EVIDENCE](TEST_EVIDENCE.md)، وحالة كل بند في [سجل التنفيذ](QA_EXECUTION_STATUS.md). الهدف المؤكد: مدرسة النسبية من جذر المستودع. لا تستخدم قاعدة إنتاج أو مستخدمي المدرسة الحقيقيين. لا تعتمد اجتياز HTTP بوصفه اختبار متصفح أو جهاز Push.

**تمييز الدفعات:** أعداد 492/492 و4004 تحققات و15/15 JavaScript و36/36 متصفح تخص دفعة 2026-11-08 بعد إصلاح الأيقونات وصفحة الخطأ. هذه نتائج تاريخية وليست الأعداد النهائية لإقفال 2026-11-09. مرجع التشغيل النظيف الأحدث وبصمة مصدره هو TEST_EVIDENCE؛ لا تُجمع نتائج النطاقات المتداخلة. الرحلات السبعة لها أدلة محلية بمستويات وحدود موضحة هناك؛ هذا لا يعني تنفيذ كل فرع يدوي أدناه أو اختبار جهاز فعلي.

سجل الملفات وبصمة الحزمة الحالية في [وثائق التسليم](../deployment/DIGITALOCEAN_HANDOFF_AR.md) وملفات manifest المرتبطة بها. **تسليم DigitalOcean هو المرجع الوحيد لأوامر البناء والنشر والترقية والرجوع في الاستضافة**؛ الأوامر أدناه محلية لا تُنسخ إلى الإنتاج. تقييم HANDOFF_READY/HANDOFF_INCOMPLETE منفصل عن PRODUCTION_NO_GO/READY_FOR_RELEASE_APPROVAL، وقرارهما في [جاهزية الإصدار](RELEASE_READINESS.md).

في إقفال 2026-11-09 نجح [قبول QA-009 المحلي](evidence/browser-qa009-closeout.json) **7/7 على PostgreSQL 17.11** بعرضي 390 و1440، ونجحت [ترقية PWA المحلية](evidence/browser-pwa-upgrade.json) **2/2** مع بقاء المسودة والخروج وتبديل الحساب والكاش العام. نافذة هذا القبول سجلت صفر ERROR/CRITICAL/EMERGENCY في [دليل السجل](evidence/closeout-ui-log-window.json)، مع إبقاء أخطاء التشغيل الأحمر السابق. تفاصيل المنهج وحدود تمثيل العامل القديم في [قبول الأجهزة وStaging](DEVICE_STAGING_ACCEPTANCE_AR.md). QA-009 التاريخي يبقى NOT_REPRODUCED، وQA-022 وQA-026 يبقيان NEEDS_DEVICE_VERIFICATION. لا تعد هذه الفحوص تثبيتًا على جهاز أو وصول Push.

## تجهيز البيانات والبيئة

جهّز إدارة اصطناعية، معلمًا مكلفًا بمادتين وصفين، معلمًا غير مكلف، طالبًا في كل صف، طالبًا خارج الجمهور، ولي أمر لطفل واحد وآخر لطفلين بصفين، ولي أمر غير مرتبط، مشرفًا مكلفًا بصف، وحسابًا غير نشط. استخدم عناوين `example.test` وأسماء تبدأ بـQA وملفات لا تحتوي بيانات شخصية. لا تضع كلمات مرور في تقرير النتائج أو الصور.

جهز مادتي `QA-MATH` و`QA-SCI` وشعبتين A/B وسنة اصطناعية، وكتابًا منشورًا معلوم الجمهور وآخر مسودة، وإعلانًا مسودة وآخر منشورًا وثالثًا منتهيًا ورابعًا لجمهور مختلف. اضبط ساعة الاختبارات أو استخدم أوقاتًا جديدة؛ لا تنقل تواريخ التقارير. اجعل التخزين والإرسال وcache محلية معزولة. لا تبدأ عامل إرسال حقيقي.

تشغيل PHPUnit الآمن من الجذر:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File scripts/qa/run-isolated.ps1 --colors=never
```

المشغل يفرض SQLite في الذاكرة ويتحقق التطبيق من اتصال الاختبار، ويخصص تخزينًا وسجلات جديدة ويفرغ بيانات اعتماد الإرسال. لا تستخدم `run-tests.ps1` الافتراضي أو `artisan migrate` على `.env` الحالي بدلًا منه.

لإعادة فحص المتصفح المحلي الآلي، اضبط QA_NODE_MODULES على مسار حزمة Playwright المحلية التي جرى التحقق من وجودها، وQA_BROWSER_EXE إذا لزم تحديد المتصفح. لا تفترض مسار مطور ثابتًا. بعد التأكد أن المنفذ 8765 غير مستخدم يمكن تنفيذ التسلسل التالي في نافذة PowerShell واحدة. ينشئ قاعدة SQLite جديدة حصريًا تحت `tmp/qa-browser`، لا يحذف قاعدة أو يعيد استخدامها. الطلبات خارج loopback محجوبة؛ تسمح فحوص PWA فقط بالعاملين المحليين. هذا مثال QA محلي، ليس أمر نشر:

```powershell
$qaPhp = (php -r 'echo PHP_BINARY;').Trim()
$env:QA_PHP_BINARY = $qaPhp
$env:QA_BASE_URL = 'http://127.0.0.1:8765'
Remove-Item Env:QA_BROWSER_PG_DESCRIPTOR -ErrorAction SilentlyContinue
if (!$env:QA_NODE_MODULES) { throw 'Set QA_NODE_MODULES to a verified local Playwright package directory.' }
if (!(Test-Path -LiteralPath (Join-Path $env:QA_NODE_MODULES 'playwright'))) { throw 'Resolve the bundled runtime path first.' }
if (Get-NetTCPConnection -LocalPort 8765 -State Listen -ErrorAction SilentlyContinue) { throw 'Port 8765 is occupied; do not reuse an unknown server.' }
$env:QA_BROWSER_RUN = (& $qaPhp scripts/qa/create-browser-fixture.php).Trim()
if ($LASTEXITCODE -ne 0) { throw 'The isolated browser fixture could not be created.' }
$qaServer = Start-Process -FilePath $qaPhp -ArgumentList @('-d','memory_limit=512M','-S','127.0.0.1:8765','-t','public','scripts/qa/browser-upgrade-router.php') -WorkingDirectory (Get-Location).Path -WindowStyle Hidden -PassThru
try {
    $qaReady = $false
    for ($qaAttempt = 0; $qaAttempt -lt 25; $qaAttempt++) {
        try { Invoke-WebRequest 'http://127.0.0.1:8765/login' -UseBasicParsing | Out-Null; $qaReady = $true; break }
        catch { Start-Sleep -Milliseconds 200 }
    }
    if (!$qaReady) { throw 'The isolated local QA server did not become ready.' }
    node scripts/qa/browser-smoke.cjs
    if ($LASTEXITCODE -ne 0) { throw 'The browser smoke checks failed.' }
    node scripts/qa/browser-learning.cjs
    if ($LASTEXITCODE -ne 0) { throw 'The browser learning checks failed.' }
    node scripts/qa/browser-academics.cjs
    if ($LASTEXITCODE -ne 0) { throw 'The browser academic checks failed.' }
    node scripts/qa/browser-tutor.cjs
    if ($LASTEXITCODE -ne 0) { throw 'The browser tutor checks failed.' }
    node scripts/qa/browser-pwa.cjs
    if ($LASTEXITCODE -ne 0) { throw 'The browser PWA checks failed.' }
    node scripts/qa/browser-qa009-closeout.cjs
    if ($LASTEXITCODE -ne 0) { throw 'The classroom acceptance checks failed.' }
    node scripts/qa/browser-pwa-upgrade.cjs
    if ($LASTEXITCODE -ne 0) { throw 'The local PWA upgrade checks failed.' }
} finally {
    Stop-Process -Id $qaServer.Id -ErrorAction SilentlyContinue
}
```

مصدر البيانات الاصطناعية هو `scripts/qa/create-browser-fixture.php`، وحماية البيئة في `browser-bootstrap.php`، والأدلة تُحفظ في `docs/qa/evidence` داخل جذر المشروع الجاري: `browser-smoke.json` و`browser-learning.json` و`browser-academics.json` و`browser-tutor.json` و`browser-pwa.json` و`browser-qa009-closeout.json` و`browser-pwa-upgrade.json`. المشغلات لا تحتاج Git أو مجلد المطور الأصلي. تجمع الأدلة بين رحلة المتصفح والفروع السلبية واختبارات الزمن والمنع في PHPUnit؛ توزيعها وحدودها في TEST_EVIDENCE. إذا ظهر فشل اتصال لأن الخادم لم يجهز، تحقق من الخادم المحلي وأعد الفحص ببيانات اصطناعية جديدة، ولا تغير هدفه إلى خادم عام.

إعادة QA-009 على PostgreSQL تحتاج قاعدة اصطناعية فارغة مستقلة وdescriptor صادرًا عن تجهيز العنقود المحلي المعزول، لا تحويل المثال إلى `.env` الحقيقي. يفحص bootstrap الغرض وmarker وhost/port/database/user/data_directory قبل migration، ويرفض fixture قاعدة غير فارغة. تضبط QA_BROWSER_PG_DESCRIPTOR قبل إنشاء fixture وتشغيل الخادم بدل مسحها في المثال. تفاصيل التحقق الفعلي في [قبول الأجهزة وStaging](DEVICE_STAGING_ACCEPTANCE_AR.md)، ونتائج PostgreSQL الشاملة والترقية في TEST_EVIDENCE. متغيرات QA_BASE_URL وQA_BROWSER_RUN وQA_BROWSER_PG_DESCRIPTOR وQA_PHP_BINARY وQA_NODE_MODULES وQA_BROWSER_EXE خاصة بالفحص المحلي وليست تغييرات بيئة إنتاج.

## بوابتا الطالب وولي الأمر

- **QA-037**: دخول الطالب الاصطناعي النشط من `/login` ثم لوحة التحكم، الدروس والاختبارات والملف. النتيجة الصحيحة لا خطأ 500. الحساب غير النشط يرفض. لا يعاد فتح العطل التاريخي الموصوف محلولًا دون فشل جديد مثبت.
- **QA-024**: افتح درسًا منشورًا لنفس الصف؛ تحقق من النص والتنسيق الآمن والملفات المدعومة والبايتات بعد التنزيل. اختبر مرفقًا مفقودًا فعليًا وبيانات قديمة اختيارية ورسالة مفهومة. الدرس المسودة/المستقبلي/لصف آخر ومرفقه ممنوع بمعرف مباشر. اسم ملف ظاهر وحده ليس إثبات رفع.
- **QA-025**: فهرس الدروس جهة اليمين عند عرض 1440، عمود قابل للطي عند عروض 360/390/768. انتقل لدرس آخر ثم للمواد؛ لا يظهر في الفهرس درس خارج النطاق أو موعده لم يحن. لا تمدد الصفحة أفقيًا.
- **QA-035**: الزر العام «رجوع» أعلى الصفحة له تنسيق موحد ومساحة لمس 44px، وحالته المرئية/keyboard focus واضحة. فتح صفحة بعد انتقال ثم رجوع يعيد الصفحة السابقة، وفي سياق جديد يستخدم fallback الموجود. راجع أيضًا زر رجوع المحادثة والرابط للمواد؛ لا تتغير سلوكياتها.
- **QA-019**: ينشر المدير إعلانًا موجهًا لأولياء صف محدد داخل نافذة النشر. الأب/الأم المرتبطان بالجمهور يريان الإعلان؛ ولي أمر صف آخر لا يراه، والمسودة والمنتهي والمستقبلي مخفيون. افتح التفاصيل بمعرف مباشر للتحقق من المنع.
- **QA-020 وQA-021**: افتح صفحة وجرس الإشعارات والرسائل بحساب ولي طفلين. اسم المعلم والصف مرتبطان بالحدث الصحيح، وبيانات الإشعار القديم لا تسبب خطأ. تحقق من حد منتصف الليل والعرض العربي مع ISO ثابت.
- **QA-023**: بعد التصحيح والنشر تظهر نتيجة الواجب/الاختبار للطالب وولي أمره فقط؛ إخفاء النتيجة يحجبها؛ لا يصل ولي أمر الطفل الآخر أو الطالب الآخر بتبديل المعرف.
- **QA-026**: اقرأ `/parent-app.webmanifest` وmanifest الطالب، واسم المدرسة المستهدفة وأيقوناتها المعتمدة وصور 192/512 الفعلية. محليًا نجحت ترقية عامل الولي v8→v9 والطالب v1→v2 بنتيجة 2/2، مع نموذج غير محفوظ وبلا reload قسري. أعدها مع التحقق من بقاء المسودة وdocument/timeOrigin، ثم الخروج والرجوع وتبديل الحساب والانقطاع: القديم الخاص ممنوع، وoffline عام، والكاش لا يحوي صفحات أو APIs أو أسماء خاصة. حدود الأيقونات الاصطناعية اللازمة لتثبيت العامل القديم في [مصفوفة القبول](DEVICE_STAGING_ACCEPTANCE_AR.md). على جهاز مصرح اختبر تثبيتًا جديدًا وتحديث النسخة القديمة الموثقة وcold start والاسم/الأيقونة؛ هذه الحالات غير منفذة هنا، لذلك يبقى NEEDS_DEVICE_VERIFICATION.
- **QA-NEW-PWA-01**: جرّب `/school-app-icon` دون شعار مهيأ ثم بمسار قديم مفقود وبنوع ملف غير مدعوم؛ المتوقع PNG معتمد 192×192 بلا 500، مع بقاء الشعار المخصص الصالح والاسم المحفوظ. افتح أيقونات shortcuts وapple-touch وصفحة خطأ، وافحص استجابات HTTP وسجل الخادم. ثبّت عاملي الطالب وولي الأمر وفعّلهما في سياقين نظيفين، ثم اقطع الاتصال وانتقل لمسارات البوابة؛ تظهر صفحة offline العامة ولا تُخزن صفحات الحساب أو APIs. نجاح التفعيل في متصفح loopback لا يغلق تحقق جهاز QA-026.
- **QA-022**: في بيئة HTTPS اختبار مصرح بها وبمشروع Push تجريبي معلوم، سجّل جهاز ولي الأمر وحده، اسمح بالتنبيهات، أغلق التطبيق وأرسل حدثًا اصطناعيًا من المدرسة. أثبت وصول الجهاز وعنوانه والنقر والعودة للحساب الصحيح، ثم ألغ الإذن/سجل الخروج وبدّل الحساب وتحقق من عدم عرض بيانات الحساب السابق. افحص queue/retries/failed_jobs والتكرار. نجحت اختبارات العامل والمزود المحاكى والخصوصية محليًا، ونجاح ترقية PWA 2/2 فحص دورة عامل وكاش فقط؛ لا يثبت وصول Push. يبقى NEEDS_DEVICE_VERIFICATION، وسجل الأجهزة والمالك والدليل المطلوب والحالات غير المنفذة في [مصفوفة القبول](DEVICE_STAGING_ACCEPTANCE_AR.md).

## المشرف وعدم التراجع

من `/supervisor/attendance` سجل حاضرًا وغائبًا ومتأخرًا، وافتح السجل والتقارير. من `/supervisor/students` أضف ملاحظة واستدعاء ولي أمر لطالب مكلف؛ أعد القراءة بحساب ولي الأمر المرتبط فقط. جرّب طالبًا غير مكلف ومعرف استدعاء مختلف. المتوقع حفظ صحيح وعدم وصول معلومات لغير المرتبط، وبقاء التفويض على الخادم.

أعد لوحة التحكم بعد إنشاء حساب/درس/اختبار، وقارن الأعداد. جرّب الدروس مسودة→مجدولة→منشورة وإلغاء الجدولة، حفظ وتسليم الواجب، كشوف المعلمين، إدارة نشر النتائج، الجداول والتعارضات، المكتبة وقراءة PDF ورفعها، استيراد قالب صحيح وفاشل، تقارير الإدارة PDF، وإعدادات المدرسة/كلمة المرور الافتراضية دون تغيير حسابات قائمة. تحقق من حفظ صورة الملف الشخصي وفتحها بعد reload إن مس المسار أي تعديل. لا تعتبر نافذة قص الصورة إثبات حفظ.

## الرحلات السبعة المتصلة

1. **إنشاء العلاقات ثم الدرس**: الإدارة تنشئ الأشخاص/الصف/المادة/الأبناء والتكليفات → المعلم ينشر درسًا بمرفق → الطالب الصحيح يفتح المحتوى وينزل المرفق → الطالب خارج الصف ومعرف المرفق المزور مرفوضان. سجل معرفات اصطناعية وعدد العلاقات بعد reload.
2. **دورة الواجب**: المعلم ينشئ دون 500 → الطالب يرفع تسليمًا → المعلم ينزل الملف ويصحح → الطالب/ولي الأمر لا يريان المسودة → نشر النتيجة يتيحها للجمهور الصحيح فقط؛ أعد الحفظ بلا تغيير للتحقق من عدم تكرار الحدث.
3. **دورة الاختبار**: إنشاء وجدولة → منع قبل الموعد → محاولة عنده وإجابات موضوعية ويدوية → حساب/تصحيح → إدارة النتائج تستورد/تراجع/تعتمد/تنشر حسب سير العمل → وصول النتيجة المقصودة فقط. اختبر نهاية النافذة وإعادة الطلب وقفل التصحيح بعد الاعتماد.
4. **المراسلات**: ولي الأمر يفتح محادثة مع المعلم ثم محادثة الإدارة → كل مشارك يفتح ويرد → نفس ترتيب الرسائل/وقت Tripoli بعد reload و poll → الحساب غير المشارك لا يقرأ ولا يرسل بالمعرف.
5. **الإعلان**: الإدارة تكتب مسودة موجهة → تحدد نافذة النشر → قبل الموعد مخفي، وعنده ظاهر، وبعد النهاية مخفي → ولي آخر خارج الجمهور لا يحصل على التفاصيل.
6. **المتابعة**: المشرف يسجل غيابًا وملاحظة واستدعاءً → ولي الطفل المرتبط يرى المعلومة → ولي آخر وطالب خارج تكليف المشرف ممنوعان؛ تحقق من السجل بعد إعادة التحميل.
7. **الصلاحيات والمالية**: الإدارة تمنح وتسحب صلاحية وتراجع منع الخادم → تطبق رسمًا عامًا وتدفع جزءًا → تعطل القالب وتراجع السجل/الأرصدة/التواريخ → وصول الطالب يتبع الإعداد دون تغيير الوصول الخاص بولي الأمر.

## مصفوفة التوثيق والقبول

لكل رحلة سجل: الوقت بتوقيت Africa/Tripoli، المرجع/بصمة الفرق، حجم 360/390/768/1440، المتصفح/الجهاز، معرف بيانات اصطناعي، الخطوات والمدخل، المتوقع/الفعلي، الاستجابة وعدد السجلات وقراءة reload، النتيجة PASS/FAIL/غير منفذ، رابط الدليل المنقح. استخدم Tab/Shift+Tab/Space/Enter/Escape واللمس، وافحص RTL والتداخل والمرشحات والقائمة والطباعة. تمرير جدول عريض مقبول داخل حاويته؛ تجاوز عرض الصفحة كاملة غير مقبول.

إذا فشل أي بند، أرفق أصغر إعادة إنتاج ومنطقة الكود المعنية دون أسرار. لا تغير الاختبار لتمرير الخطأ، ولا تعطل صلاحية أو تتجاوز قاعدة مرتبطة. QA-016 لم يعد ينتظر قرار سياسة؛ اعتمد المستخدم حذف المخصص المثبت وغير المسند فقط، وتظل السجلات مجهولة المنشأ محمية.

لإعادة النظر في قرار الإنتاج يلزم إغلاق QA-022 وQA-026 على جهاز مصرح، واستكمال QA-009 التاريخي بسيناريو مماثل للمصدر أو قبول بديل موثق صراحةً دون ادعاء معرفة السبب. قبول QA-009 الحالي ناجح 7/7 محليًا ولا يغيّر حالته التاريخية تلقائيًا. يبقى مجموع حالات البنود الأصلية 27 FIXED_LOCAL_TESTED و7 ALREADY_FIXED_VERIFIED و1 NOT_REPRODUCED و2 NEEDS_DEVICE_VERIFICATION؛ لا VERIFIED_IN_TARGET_ENV.

اختبارات PostgreSQL المحلية نُفذت، ومرجع نتائج الإنشاء والترقية والتزامن والمصدر المفكوك هو TEST_EVIDENCE؛ لا تُوصف بأنها غير مختبرة عمومًا. يبقى تأكيد إصدار DigitalOcean الفعلي وخدماته وعماله وجدولته ونسخه الاحتياطية والاستعادة وقبول staging منفصلًا. عند إعادة الترقية اختبر بقاء محادثة طالب قديمة ورسائلها، ورفض down الثاني قبل أي تعديل إذا وجدت محادثة معلم؛ لا تحذف البيانات لتسهيل الرجوع. قبول Gemini الحقيقي والأجهزة وstaging موثق بخانات «غير منفذ» ومالك ودليل مطلوب في [مصفوفة القبول](DEVICE_STAGING_ACCEPTANCE_AR.md). لا تدخل الفجوات في المنجز، ولا تصبح اختيارية تلقائيًا؛ أي استثناء يحتاج اعتمادًا بشريًا صريحًا موثقًا. يؤخذ تسلسل النشر والرجوع من [تسليم DigitalOcean](../deployment/DIGITALOCEAN_HANDOFF_AR.md) وحده، ولا ينفذ قبل الاعتماد المنفصل.
