## التغييرات والأسباب المؤكدة

- إعلان الإدارة يعلن منطقة الإدخال عبر `schedule_timezone` ويحوّل الأوقات بعد التحقق إلى UTC. النموذج والقائمة يعرضان منطقة المدرسة بوضوح. بقي `app.timezone=UTC`، وبقيت طلبات API القديمة دون منطقة على عقد UTC؛ القيم ذات offset تحافظ على اللحظة. لم تعدل سجلات تاريخية ولم تضف ساعتان يدويًا. أخطاء النموذج تحتفظ بالنص المحلي الأصلي.
- البحث في عنوان/محتوى الإعلان يجتمع مع الجمهور والحالة والصف/الشعبة، ويحتفظ بالفلترة في الصفحات. التطبيق مخصص لمدرسة واحدة لكل deployment؛ لا يوجد tenant اختير من مدرسة أخرى.
- يتوافق إرسال الطلاب وعرضهم الآن مع نطاق `classroom_id` حتى عند اختيار «الجميع» أو «الطلاب»؛ كان إشعار الطالب يتجاهل هذا القيد بينما قنوات أخرى تحترمه. تغطي الاختبارات طالبًا داخل الصف وآخر خارجه ووليًا مرتبطًا.
- الحذف المادي مقتصر على مسودة بلا إشعارات أو أحداث FCM. الأرشفة تخفي الإعلان وتحفظ السجل وتلغي الأحداث غير المعالجة. طلب الأرشفة المتكرر لا يكرر سجل التدقيق. إعادة نشر إعلان مؤرشف تعيد ظهوره وفق النطاق الحالي، لكنها لا تعيد إرسال حدث Push ملغى أو تسلّم نسخة ثانية من الإشعار؛ إعلان جديد مقصود يحتاج سجلًا جديدًا.
- ترحيل إضافي `2026_11_11_000001_add_fcm_event_cancellation.php` يضيف `cancelled_at` و`cancellation_reason` فقط. لا يحذف صفوفًا ولا يغيّر أحداثًا قديمة. العامل يعيد التحقق من الظهور والاستهداف عند تنفيذ مهمة إعلان، ولا يرسل مهمة ملغاة أو منتهية أو أعيد توجيهها إلى صف آخر. لا تُكتب `sent_at` بوصف الإلغاء تسليمًا.
- يمتد فحص العامل إلى إشعارات النتائج: يجب أن تبقى الفترة منشورة وبالمراجعة نفسها، وأن تبقى نتيجة الطالب في إسقاط النشر الحالي، وأن يكون المستلم الطالب نفسه أو وليًا ما زال مرتبطًا به. تُلغى المهمة القديمة عند الإخفاء أو إعادة المراجعة أو سحب النتيجة أو فك ارتباط الولي، مع حفظ الحدث وسبب الإلغاء. يستعمل ذلك سياسة النشر الحالية ولا يتيح للمعلم تجاوزها.
- حفظ/تعديل الإعلان والتدقيق والإشعار الداخلي/outbox في معاملة واحدة. فشل إدراج داخلي يلغي الحفظ بدل استجابة فشل بعد حفظ جزئي؛ تعطل إدراج الطابور يبقي الحفظ ناجحًا والحدث قابلًا للاسترداد بواسطة `fcm:retry-pending`.
- البنية الموجودة موقع/PWA، وليست عميلًا أصليًا مثبتًا في هذا المستودع. FCM يستخدم خدمة ويب ورمز جهاز ومشروع Firebase وعاملًا منفصلًا، وللولي قناة Web Push/VAPID منفصلة. حالات عدم الدعم/رفض الإذن/عدم التهيئة/فشل التحقق تظهر برسالة صادقة، مع إبقاء إشعارات المنصة وخيارات التفعيل الأخرى. لا يساوي إذن المتصفح أو `sent_at` وصول إشعار لهاتف.
- لم تُعد كتابة المساعد. مسارا المعلم والطالب ينشئان الجلسة في قاعدة البيانات، ويحفظان الرسالة وحالة فشل صريحة عند غياب المزود، ولا يختلقان جوابًا. الاختبارات المحاكية الحالية تحققت من الرد الناجح والمهلة وحدود المعدل والعزل والتكرار واسترداد السؤال المعلق. التهيئة الحية ما زالت مطلوبة.

إلغاء الإعلان يمنع **العمل المعلّق الذي لم يبدأ الإرسال**. لا يمكن سحب رسالة قبلها المزود بالفعل أو إلغاء مكالمة شبكة تجاوزت فحص الأهلية قبل الأرشفة. هذه نافذة تنفيذ حقيقية؛ لا ندعي atomic cancellation مع مزود خارجي أو exactly-once.

## تسليم التشغيل وحدود القبول

المرجع التنفيذي الحالي هو `docs/deployment/ROUND_2_HANDOFF_AR.md`؛ تسليم DigitalOcean السابق سجل تاريخي. يجب تطبيق ترحيلي الجولة الثانية بالترتيب المبين قبل تشغيل الكود والعامل الجديد، وبناء `public/build` من القفل عبر `npm ci --ignore-scripts` و`npm run build` لتحديث رسائل FCM، ثم تجديد config/route/view caches وفق المرجع وإعادة تحميل العمليات طويلة العمر. لا اعتماد جديد ولا أسماء مفاتيح إنتاج جديدة. `APP_DISPLAY_TIMEZONE` الموجود يضبط أوقات نموذج الإعلان الآن أيضًا؛ الافتراضي `Africa/Tripoli` والتخزين UTC.

يتحقق المسؤول من مطابقة إعدادات Firebase العامة وقت البناء للمشروع والخادم، وحماية ملف حساب الخدمة خارج public/Git، وخدمة database queue والمجدول القائم (`announcements:notify-due` و`fcm:retry-pending` كل دقيقة). لا يعاد تشغيل إشعارات قديمة جماعيًا. قناة VAPID متزامنة منفصلة ولا ترث outbox أو cancellation markers تلقائيًا؛ إعلان مؤرشف لا ينتج بثًا جديدًا عبر مسار النشر، لكن إرسالًا جاريًا لا يمكن سحبه.

التراجع: احتفظ بالمخطط المضاف والتاريخ. `down()` يرفض إسقاط أعمدة الإلغاء عند وجود أحداث ملغاة. **إبقاء الأعمدة وحده لا يكفي لتشغيل عامل قديم** يتجاهل الإلغاء: أوقف العمال قبل التراجع واحتفظ بعامل متوافق يحترم الإلغاء أو اعتمد معالجة محددة للمهمات الملغاة دون حذف التاريخ. لا تستعد نسخة قاعدة قديمة فوق إجابات أو درجات أو مراسلات جديدة. لم ينفذ أي أمر استضافة.

القبول الإنتاجي المعلق: بحسابات اختبار معتمدة فقط، إعلان فوري ثم إعلان بوقت المدرسة عبر منتصف الليل، ظهور/انتهاء صحيحان للطالب والولي، أرشفة قبل موعد الإرسال، ثم إذن/رفض/تثبيت PWA وإشعار هاتف مغلق ونقرة وLogout وتبديل حساب على الأجهزة المدعومة. اختبر Gemini برد تعليمي عام للطالب والمعلم دون بيانات شخصية بعد إعداد المزود. لا تعرض مفاتيح أو رموز أجهزة أو محتويات محادثات في سجل القبول.
