**هذا سجل مرحلي عند تجميد دفعة PostgreSQL، وليس قرار القبول النهائي للمصدر الكامل المفكوك.** النتائج النهائية الحالية للحزمة وبصمتها في `docs/qa/TEST_EVIDENCE.md`؛ تبقى الأعداد أدناه تاريخية وصحيحة للتشغيل المحدد ولا تُستبدل بصمت.

**نتيجة الدفعة:** نجح إنشاء مخطط فارغ، وترقية بيانات قديمة اصطناعية عبر الترحيلين الجديدين، وفحص الملكية والقيود والطابور، واستعادة نسخة اصطناعية على **PostgreSQL 17.11** فعلي. نجحت المجموعة الكاملة وقتها: **507 اختبارات، منها 506 ناجحة وواحد متخطى خاص بـSQLite، و4123 تأكيدًا**. شُغّل اختبار الشعبة الفارغة المضاف لاحقًا مع ملفه منفصلًا: **5 اختبارات و40 تأكيدًا ناجحة**. هذه نتائج محلية محددة، ولا تثبت مطابقة إصدار قاعدة الاستضافة أو نجاح نشر إنتاجي.

الدليل القابل للقراءة آليًا: [postgres-validation.json](evidence/postgres-validation.json). يتضمن بصمات الأدلة، ونتائج الفحوص، وأعداد الصفوف الاصطناعية وبصماتها؛ لا يحتوي كلمات مرور أو dump أو بيانات مستخدمين حقيقية.

- بيئة PHP الفعلية: **8.4.21**، مع `pdo_pgsql` و`pgsql`. المحرك: `PostgreSQL 17.11 on x86_64-windows, compiled by msvc-19.44.35229, 64-bit`.
- لا تعليمات `AGENTS.md` جديدة تنطبق على الجذر أو مسار المهمة. لم تُقرأ `.env` الحقيقية ولم تُستخدم بيانات اتصال الاستضافة. تمنع نقطة bootstrap تحميلها وتمنع config cache السابق؛ البريد array وHTTP غير المزيف ممنوع، واتصال الطابور مثبت على قاعدة الاختبار نفسها.

## المخطط السابق والترقية والاستعادة

استُخدم `git archive` فعليًا على المرجع المثبت لتصدير **42 ملف migration سابقًا** وملفي `config/school_accounts.php` و`config/smart_tutor.php`. ليس هذا نسخة كاملة من التطبيق القديم؛ إنه مخططه التاريخي وإعدادات تحتاجها تلك الترحيلات. بُنيت قاعدة جديدة من هذه الملفات ثم زُرعت بيانات اصطناعية بتاريخ سابق: خمسة مستخدمين، طالبان، ثلاثة ملفات معلمين، محادثتان ورسالتان قديمتان، وجهاز وهمي وثلاث حالات FCM قديمة، منها تسليم جزئي.

طبّق فحص الترقية الملفين التاليين فقط، دون تغيير ملفات migrations القديمة:

- `2026_11_08_000001_add_fcm_outbox_payload.php`.
- `2026_11_08_000002_add_teacher_owner_to_tutor_conversations.php`.

نتيجة التشغيل الأول من Git: **32 فحصًا ناجحًا**؛ خمسة لبناء المخطط السابق، و23 للترقية، وأربعة للاستعادة. الدليل المحلي تحت `tmp/qa-postgres/f3cf6e5850524d9297895b0002399a56/upgrade-9048c3fea6c1432a9b7aa924609f9ce3`.

الفحوص تثبت الآتي:

1. لا نقل لمحادثة طالب قديمة إلى معلم، ولا backfill لبيانات إرسال قديمة، ولا إعادة طابور لحالات FCM القديمة ذات payload فارغ.
2. قيود FK القديمة والجديدة ترفض المالك غير الموجود بـ`23503`، والقيد المركب يرفض تكرار معرف إنشاء المعلم نفسه بـ`23505` ويسمح بالمعرف نفسه لمعلمين مختلفين.
3. نطاق الطالب يخفي المحادثة ذات الملكية المزدوجة، ونطاق المعلم يستبعد ملكية غيره. الخدمة ترفض الصف بلا مالك أو ذا مالكين قبل مزود الذكاء. هذه صفوف تالفة مصطنعة للاختبار؛ قاعدة البيانات تسمح بها، وطبقة التطبيق ترفض استعمالها.
4. الرجوع قبل وجود سجل معلم جديد يحفظ جميع قيم البيانات القديمة في **12 جدولًا** بحسب عدد الصفوف وSHA256. بعد وجود سجل معلم أو سجل بلا طالب، يرفض `down` قبل تغيير البيانات؛ لا حذف لسجل المعلم لتجاوز الحارس.
5. تعذر إدراج job يبقي حدثًا جديدًا قابلًا للاسترداد؛ retry يدخله مرة واحدة، وتكرار المصدر أو retry لا يولد job آخر. فشل DDL محقون داخل معاملة PostgreSQL يعيد الأعمدة وpayload والصفوف كما كانت. إعادة `migrate` بعد التطبيق لا تغيّر الصفوف أو سجل migrations.
6. أُخذت نسختان اصطناعيتان فعليتان بـ`pg_dump -Fc` قبل الترقية وبعدها. أُعيدت نسخة ما بعد الترقية إلى `nasbia_qa_restore` الفارغة بـ`pg_restore --exit-on-error`. تطابقت قيم الصفوف وبصماتها في الجداول الاثني عشر؛ خصصت sequence المحادثات معرفًا جديدًا غير مستخدم، وبقي payload وعلامة إدراج الطابور محفوظين.

النسخ الثنائية تحت tmp فقط، ولا تدخل الحزمة. لا يعني اختبار `down` قبل بدء الميزة أن عكس مخطط outbox آمن بعد بدء الإرسال: حذف payload وqueued_at يفقد معلومات الاسترداد. عند رجوع شيفرة التطبيق بعد الاستخدام، يُحفظ المخطط الموسع إلى حين معالجة السجل الجديد وفق خطة الاستضافة.

## إعادة التحقق دون Git

يحتوي [BASELINE_MIGRATIONS.json](../deployment/BASELINE_MIGRATIONS.json) قائمة غير تنفيذية ببصمات SHA256 لبايتات الملفات الأربعة والأربعين من أرشيف Git الذي استُخدم فعليًا. لا توجد نسخة ثانية تنفيذية من migrations في الحزمة. يتحقق المشغل من كل ملف ومن جرد المخطط بالكامل، ثم يصنع نسخة مؤقتة تحت مجلد QA من الملفات المطابقة فقط، مستبعدًا الترحيلين الجديدين.

عند غياب `.git` يُختار manifest تلقائيًا. ويمكن فرضه صراحة باستخدام `-BaselineManifest`. أي ملف مفقود أو زائد أو متغير البصمة أو مسار غير آمن يوقف التشغيل قبل مرحلة ترحيل PHP. البصمات تطابق البايتات حرفيًا؛ تحويل LF إلى CRLF يُرفض، ولا يُخفى تحت تطبيع نهايات الأسطر.

اختُبر هذا النمط فعليًا على عنقود جديد 55441: **32/32 ناجحة** مرة أخرى. الدليل تحت `tmp/qa-postgres/1da957fa7a3c40cdb935f179e7c75681/upgrade-fb19698de3ec45b8bed7a2d0de5f89bf`. واختبار manifest ذي بصمة متعمدة الخطأ نجح في الرفض قبل الترحيل. أُوقف هذا العنقود بعد التحقق. يفصل `baseline-origin.json` وضع `verified-source-manifest` عن وضع Git؛ يحتفظ JSON النهائي ببصمة أرشيف Git الفعلي الأول أيضًا.

كشف المتصفح على PostgreSQL أيضًا خطأ تحقق فعليًا في IDs غير الرقمية للصفوف: كانت تصل إلى مقارنة integer في قاعدة البيانات وتعيد 500. عالج منفذ الواجهة `ClassroomRequest` بالتحقق من نوع المعرف قبل exists/unique؛ أكد النطاق المستقل أعلاه رفضها بـ422 وحفظ سلوك الشعبة الفارغة. تفاصيل المتصفح في دليل منفذ الواجهة. دليل تنافس FCM الفعلي بعمليتي PHP يملكه منفذ التعلم في [fcm-postgres-concurrency.json](evidence/fcm-postgres-concurrency.json)، ويُقرأ مستقلًا عن فحوص الترقية هذه.

## أوامر إعادة الإنتاج

نفّذ من جذر المصدر بعد تجهيز متطلباته المحلية. قيمة PgBin مسار محرك موجود؛ لا يحمل المشغل محركًا أو يثبته. كل تشغيل ترقية يحتاج عنقودًا جديدًا لأن الأداة ترفض إعادة استخدام قاعدة غير فارغة.

```powershell
$qaPgBin = 'C:/Users/pixel/AppData/Local/Temp/awf-fcm-pr8-postgres-review-20261101/pgsql/bin'
powershell.exe -NoProfile -ExecutionPolicy Bypass -File scripts/qa/start-postgres.ps1 -PgBin $qaPgBin -Port 55441
# ضع قيمة QA_POSTGRES_MARKER المطبوعة من إنشاء العنقود الجديد:
$qaMarker = 'C:/path/to/source/tmp/qa-postgres/NEW_RUN/cluster.json'
powershell.exe -NoProfile -ExecutionPolicy Bypass -File scripts/qa/validate-postgres-upgrade.ps1 -Marker $qaMarker -BaselineManifest docs/deployment/BASELINE_MIGRATIONS.json
powershell.exe -NoProfile -ExecutionPolicy Bypass -File scripts/qa/run-postgres.ps1 -Marker $qaMarker --colors=never
powershell.exe -NoProfile -ExecutionPolicy Bypass -File scripts/qa/stop-postgres.ps1 -Marker $qaMarker
```

في checkout الذي يملك كائن Git المثبت يمكن حذف `-BaselineManifest` لاختبار التصدير المباشر. في المصدر المفكوك دون `.git` يكفي حذف الخيار أيضًا ويختار الملف المرفق تلقائيًا. لا تشغّل مجموعتين بالتوازي على `afhamha_testing` نفسها. إذا استُعمل العنقود الموجود لاختبار مصدر مفكوك، يدعم `run-postgres.ps1 -SourceRoot 'C:/path/to/extracted/source'` مع marker الأصلي؛ الترقية تحتاج قواعد جديدة فارغة كما سبق. لا تشغّل أداة الإيقاف قبل انتهاء مستخدمي العنقود المتفق عليهم.

## الحدود المتبقية

إصدار PostgreSQL الفعلي في الاستضافة غير مثبت من مصدر متاح؛ وثائق المشروع القديمة تشير إلى PostgreSQL على Ubuntu 24.04 دون رقم إصدار. الاختبار الحالي يثبت Windows/PostgreSQL 17.11 فقط، ولا يثبت توافق إصدار أقدم أو Linux أو إعدادات الاستضافة. لا بيانات إنتاج أو مزود FCM/Gemini حقيقي أو جهاز Push ضمن هذا الدليل.

حجم البيانات الاصطناعية صغير. لم يُقَس زمن أقفال DDL أو بناء الفهرس أو مدة dump/restore على حجم الإنتاج، ولم تُنفذ استعادة إلى خدمة مُدارة. يبقى ضبط نافذة الترحيل والنسخة الاحتياطية وأداء الاستضافة ضمن التسليم التشغيلي. تبقى الملفات الثنائية لمحرك PostgreSQL، وبيانات عناقيد QA، وdumps، وأرشيف المخطط المؤقت خارج حزمة المصدر.
